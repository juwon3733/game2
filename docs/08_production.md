# 08. 제작 계획

## 1. 엔진

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **Godot 4** | 무료, 가벼움, 2D 도트에 강함(픽셀 스냅, 정수 스케일), 드래그 앤 드롭 UI 구현 쉬움, PC/웹/모바일 내보내기 | 한국어 자료가 Unity보다 적음 | **추천** |
| Unity | 자료 많음, 모바일 경험 활용 | 무겁고 2D 도트 설정이 번거로움, 라이선스 이슈 이력 | 차선 |
| 웹 (TypeScript + Phaser/PixiJS) | 브라우저에서 바로 공유, 프로토타입 최고 속도 | 스팀 출시 시 Electron 패키징 필요, 세이브/성능 관리 직접 | 프로토타입 전용으로 고려 |

**결정 제안**: 퍼즐 감각 확인용 **회색 박스 프로토타입은 웹으로 빠르게** 만들고, 확인되면 **본 개발은 Godot 4**로 간다. (미정 사항 문서 참고)

## 2. 스토리 툴

- 대사와 분기: **Yarn Spinner** 또는 **Dialogic 2**(Godot 플러그인). 대사 파일을 코드와 분리해 현지화 대비.
- 컷 데이터: JSON (04_systems.md 데이터 구조). 컷 에디터를 Godot 에디터 플러그인으로 직접 만든다.
- 장 데이터: 장별 JSON에 컷 묶음, 정답 배열, 대사 조각, 심문 스크립트 참조를 정의.

## 3. 저장소 구조 (제안)

```
same-day-different-panel/
├─ docs/                  기획 문서 (지금 이 폴더)
├─ prototype/             회색 박스 프로토타입 (웹)
├─ game/                  Godot 프로젝트
│  ├─ scenes/
│  ├─ scripts/
│  ├─ data/
│  │  ├─ cuts/            컷 JSON
│  │  ├─ chapters/        장 JSON
│  │  └─ dialogue/        대사 파일
│  └─ assets/
│     ├─ sprites/
│     ├─ cuts/            컷 레이어 PNG
│     ├─ portraits/
│     ├─ ui/
│     ├─ fonts/
│     └─ audio/
└─ art_source/            Aseprite 원본 (.aseprite) — 용량이 커지면 Git LFS
```

브랜치 운영: `main`은 항상 실행 가능한 상태로, 작업은 기능별 브랜치(`proto/cut-puzzle`, `ch1/interrogation` 등)에서.

## 5. 마일스톤

| 단계 | 목표 | 산출물 | 완료 기준 |
|---|---|---|---|
| **M0. 기획** | 기획서 확정 | `docs/` 전체 | 미정 사항 중 엔진, 주인공 디자인 결정 |
| **M1. 퍼즐 프로토타입** | 컷 배열이 재밌는지 확인 | 웹 회색 박스: 1장 1차 4칸 + 최종 6칸, 말풍선 1개 | 지인 3명 이상이 설명 없이 풀고 "재밌다" |
| **M2. 심문 프로토타입** | 끼워 넣기가 재밌는지 확인 | 1장 심문 1~2 (회색 박스) | 반박 성공의 쾌감이 있는지 |
| **M3. 아트 테스트** | 그림체 확정 | 레이/코하루 초상, 1장 컷 3장, 맵 1개 | 스크린샷 1장으로 "무슨 게임인지" 보임 |

| **M5. 데모** | 외부 공개 | 프롤로그 + 1장 (+ 2장 일부) | itch.io / 스팀 넥스트 페스트용 |
| **M6. 본편** | 2~5장 | 전체 빌드 | |
| **M7. 출시 준비** | 현지화, QA, 스토어 | 스팀 페이지, 트레일러 | |

## 6. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 컷 수가 너무 많음 | 아트 일정 폭발 | 모듈 조립, 왜곡은 셰이더, 핵심 컷만 전용 작화 |
| 퍼즐이 너무 쉽거나 어려움 | 재미 붕괴 | M1에서 반복 테스트. "컷만 보고 유일하게 풀리는가" 체크리스트 |
| 정답이 여러 개로 해석되는 배열 | 플레이어 불만 | 모든 배열 퍼즐에 상태 태그를 붙이고, 툴로 "다른 정답이 가능한지" 자동 검사 |
| 스토리 분량이 커서 미완성 | 출시 불가 | 1장을 완성품으로 먼저 만들고, 2장 이후는 1장 템플릿 재사용 |
| 가짜 컷 판별이 픽셀 헌팅이 됨 | 피로 | 이음매 유형을 미리 가르치고, 돋보기 + 토와 분석으로 범위를 좁혀줌 |
| 무거운 소재(화재, 죽음) | 톤 붕괴 | 잔상과 일상 파트와 카페 파트로 호흡 조절. 직접적인 고어 묘사 금지 |
